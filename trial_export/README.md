# Example trial export: generating file + TITE-CRM output

Generated by `generate_trial_export.py` at the repo root:

```
python3 generate_trial_export.py --seed 20260805 --scenario "Acute middle"
```

This runs **one** simulated trial through `sim.run_tite_crm()` and writes out
two files that separate the two things Sama wants to compare independently:
the *generated patient data* and the *model's decisions on that data*.

## `generating_file_trial1.csv` — the ground truth

One row per patient (30 total: 6 pre-treated + 24 new), in enrollment order.
This is the "which of the 30 patients gets a DLT and when, and when OK
(surgery) happens" file — the same role as the generating file Sama builds by
hand before feeding it into her R TITE-CRM fit.

| column | meaning |
|---|---|
| `patient_id` | 1..30, enrollment order |
| `is_pretreated` | True for the 6 patients pre-loaded at L1 before day 0 (safely-treated history) |
| `dose_level` / `dose_label` | dose level (0-based, L0..L4) and label the patient was actually treated at |
| `arrival_day` | calendar day of inclusion (negative for pre-treated patients) |
| `rt_start_day` | radiotherapy start day |
| `dlt1_acute` / `dlt1_day` | acute DLT (tox1) occurrence and day |
| `tox1_fu_end_day` | day acute follow-up window closes |
| `ok_performed` / `ok_day` | whether/when surgery took place |
| `dlt2_subacute` / `dlt2_day` | subacute DLT (tox2) occurrence and day (only defined if surgery happened) |
| `tox2_fu_end_day` | day subacute follow-up window closes |

## `tite_crm_output_trial1.csv` — our model's decisions on that data

One row per cohort decision (dose escalation/de-escalation step), in the
order the trial actually ran. Includes the TITE-weighted n/y per dose level
at decision time, the CRM posterior mean and overdose probability per dose
for both endpoints, which doses were EWOC-admissible, the dose assigned to
the next cohort, and the reason for that choice.

## `trial1_summary.json`

The scalar outputs (final selected MTD, total study days, early-stopping
flag) plus every setting and true probability used to generate this trial,
so the run is fully reproducible (`--seed 20260805 --scenario "Acute
middle"`).

## Purpose

Feed `generating_file_trial1.csv` into Sama's R model and compare her fitted
decisions/MTD against `tite_crm_output_trial1.csv` / `trial1_summary.json`.
Because both come from the *same* generated patients, any difference in the
recommended dose per cohort or the final MTD must come from how the model is
fit (posterior/EWOC logic), not from how the data was generated. Re-running
`sim.run_tite_crm()` directly on the same generating file (rather than only
comparing R vs. Python here) is the cleanest way to isolate that further,
once Sama's R code is available.

## Known differences worth checking against Sama's R code

See the accompanying email discussion — in short:

1. **Surgery postponement is not currently modelled.** `p_surgery` is a
   single Bernoulli "does surgery happen at all" probability, and
   `rt_to_surg` (RT-end-to-surgery gap) is a fixed constant, not a random
   delay. There is no probability-of-postponement + delay-distribution
   mechanism, so it doesn't yet affect TITE partial-follow-up weighting the
   way Sama's model does.
2. **Dose-assignment rule depends on EWOC on/off.** With EWOC on (the
   default, `ewoc_alpha=0.35` in this export), `crm_choose_next()` already
   picks the *highest* dose level jointly admissible under the EWOC overdose
   filter for both endpoints — matching Sama's "highest dose below target"
   approach, but expressed as an overdose-probability threshold rather than
   a direct comparison of the posterior mean to the target. With EWOC off,
   the code instead picks the dose whose posterior mean is closest to the
   target (standard CRM). Worth confirming which of these two rules (or a
   third, direct "highest posterior mean < target" rule) matches Sama's R
   code once it's available.
